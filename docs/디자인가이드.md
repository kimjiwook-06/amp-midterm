# 디자인 가이드 — 어디 뒀지? v2

## 1. 제품과 범위
사진으로 기록하고 말로 찾는 AI 물건 찾기 도우미. 생산성 앱. Itemtopia의 재고 관리 기능을 그대로 복제하는 것이 아니라, 일상 물건의 **마지막 기록 위치를 재발견**하는 흐름에 집중한 독립 v2 콘셉트다. 기존 앱의 공식 후속 버전은 아니다.

Flutter UI만 구현한다. GET /items는 실제 로컬 json-server 요청이다. AI·음성·사진 선택·저장·검색은 고정 시나리오이며 사용자 개인정보, 외부 AI API, 영구 저장을 사용하지 않는다. 모든 화면은 아래 목록에 포함한다.

## 2. 화면 흐름 / 요소 분석
A 물건 찾기 → Navigator.push → B 물건의 자리 → showModalBottomSheet → C 발견 완료 → popUntil → A.
A 사진으로 새 기록 → Navigator.push → D 사진 기록(선택→분석→검토→완료) → pop → A.
A 내 기록은 NavigationBar/상단 버튼으로 같은 목록 표현을 전환한다. B는 TabBar(위치 / 물품 정보). 음성 예시, 데모 상태, 안내는 덮기 방식이다.

| 번호 | Flutter 위젯 / 비즈니스 명칭 | 전달할 정보·판단 기준 | 원칙·이유 |
|---|---|---|---|
| A-1 | TextField / 특징 검색 | 이름 대신 색깔·용도도 입력 가능. Enter와 버튼이 동일한 결과 | P02 현실 언어, P06 기억 부담 감소 |
| A-2 | ActionChip / 검색 예시 | 음악·검은색·충전의 3가지 진입 예시 | P06 재인, P07 빠른 경로 |
| A-3 | OutlinedButton / 사진 기록 | 촬영이 아니라 예시 사진으로 흐름을 경험 | P07 빠른 기록 시작 |
| A-4 | InkWell / 물건 카드 | 이름→특징→마지막 위치→시각 순서. 클릭 시 상세 | P06 카드에서 후보 비교 |
| A-5 | FutureBuilder / 기록 상태 | 로딩·오류·빈 기록·성공을 구분. 오류는 재시도, 빈 기록은 기록하기 | P01 상태 가시성, P09 회복 경로 |
| A-6 | NavigationBar / 주요 탐색 | 찾기·내 기록·사진 기록. 800px 이상은 상단 탐색 | P04 일관된 명칭 |
| B-1 | Text / 물건 이름 | 사용자가 선택한 후보가 맞는지 확인 | P02 익숙한 이름 |
| B-2 | ScenePhoto / 사진 위치 | 원본 사진과 연두색 경계로 예시 위치 강조 | P06 보면서 찾기 |
| B-3 | TabBar / 위치·물품 정보 | 주 과업인 위치를 기본 탭으로, 나머지는 보조 | P04 표준 탭, P08 정보 집중 |
| B-4 | Text / 마지막 기록 | 기록 시점과 이동 가능성을 함께 표기 | P01 실시간 추적 오해 방지 |
| B-5 | FilledButton / 찾았어요 | 발견 완료 피드백. 실제 기록 삭제 없음 | P03 사용자가 완료 결정 |
| C-1 | Icon / 완료 피드백 | 체크 아이콘과 제목을 함께 제공 | P01 상태 가시성 |
| C-2 | Text / 찾은 물건 | 어떤 물건을 찾았는지 문맥 유지 | P02 현실 언어 |
| C-3 | Text / 시연 안내 | 기록이 바뀌지 않는다는 안내 | P01 정직한 시스템 상태 |
| C-4 | FilledButton / 돌아가기 | 다른 물건을 찾을 수 있게 홈으로 복귀 | P03 통제와 자유 |
| D-1 | Wrap / 진행 단계 | 사진 선택→물건 확인→기록 완료, 색과 숫자 병행 | P01 진행 가시성 |
| D-2 | ScenePhoto / 예시 사진 | 실사진 대신 합성 예시 이미지, 카메라 권한 없음 | P06 사진과 후보 대조 |
| D-3 | CheckboxListTile / 검토 목록 | 확인된 후보는 기본 선택, 불확실한 이름은 글자로 표시 | P05 오류 예방 |
| D-4 | AlertDialog / 정보 수정 | 이름 수정·취소. 빈 이름은 적용하지 않음 | P03 취소, P05 입력 오류 방지 |
| D-5 | FilledButton / 확인·모의 완료 | 선택 개수 표시. 0개면 비활성화. 실제 저장 없음 | P01 피드백, P05 잘못된 확정 예방 |
| D-6 | TextField / 장소 이름 | 기본 장소 제공, 최대 50자. 검토 후 완료 화면에 반영 | P02 현실 공간 표현 |
| O-1 | BottomSheet / 음성 미리보기 | 예시 문장 확인→검색. 마이크 미사용 고지 | P03 실행 전 확인 |
| O-2 | BottomSheet / 데모 장면 | 정상·로딩·오류·빈 기록 전환 | P01 상태 시연 |
| O-3 | AlertDialog / 이용 안내 | 고정 검색 예시와 프로토타입 범위 설명 | P10 도움말 |

## 3. 시각 규칙
- 배경 #F7F8F4, 카드 흰색, 핵심 행동 #275C48, 본문 #283B32, 보조 #6A786E, 경계 #E1E6DE.
- Noto Sans KR를 로컬 번들로 제공한다(OFL). 외부 폰트 서버 연결 없이 한글 표시.
- 제목 24–43, 본문 14–16, 보조 11–13. 중요 위치 문장은 색만으로 구분하지 않는다.
- 8px 기반 간격(8/16/24/32). 카드 20–24px, 버튼 16px 반경. 주 버튼 최소 높이 52px.
- 상세의 위치 경계는 사진 위에 표시하며 이름 라벨을 병기한다. 좌표는 예시 데이터이며 AI 정확도를 나타내지 않는다.
- 휴대폰은 세로 스크롤, 800px 이상 홈은 좌우 2열. 카드 영역 560/900px에서 2/4열. 상세 760px, 기록 740px에서 2열. 창 너비 기준이며 기기 판별로 레이아웃을 바꾸지 않는다.
- 로딩 중 가짜 진행률 숫자를 제시하지 않는다. 실패 시 화면에 오류와 재시도를 유지한다. 결과 0개와 서버 실패는 다른 화면이다.

## 4. 디자인 가이드 글
사용자는 물건을 정리하려고 앱을 여는 경우도 있지만, 대부분 급하게 무언가를 찾고 싶어서 연다. 첫 화면에서 검색을 최우선으로 제공한다. 정확한 제품명 대신 사용자의 기억에 남는 색과 용도를 입력하게 하고, 검색 예시로 시작 부담을 낮춘다. 후보 카드에는 위치를 숨기지 않는다. 상세에서는 사진과 위치 설명을 나란히 배치하여 공간을 바로 떠올리게 한다. 사진 분석은 결론이 아니라 초안으로 다룬다. 사용자 확인 없이 확정하지 않으며, 불확실한 항목만 강조하여 검토 부담을 줄인다. 기록 날짜를 항상 노출해 오래된 사진을 현재 위치로 오해하지 않게 한다.

## 5. 상태관리 포인트 (설계만)
| 향후 상태 | 관련 위젯 | 현재 데모 구현 / 실제 구현 안 함 |
|---|---|---|
| 기록 목록·네트워크 상태 | A-4/A-5 | FutureBuilder + GET. 캐시/동기화/저장소 없음 |
| 검색 의도·후보·선택 | A-1/A-4/B-1 | setState로 정해진 예시만 선택. 임베딩/추천 모델 없음 |
| 인식 후보·확인 여부 | D-3/D-4 | 화면 안 변수만 변경. 분석 모델·영구 저장 없음 |
| 위치 업데이트·기록 시간 | B-4 | 고정 예시. 실제 위치 추적 없음 |
| 음성 권한·전사 | O-1 | 예시 문장 표시. 권한 요청/녹음 없음 |

코드에서 `STATE:`로 향후 상태 경계를 찾는다. Provider/Riverpod/Bloc 등은 추가하지 않았다.
