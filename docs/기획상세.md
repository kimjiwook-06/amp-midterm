# 기획 상세 — 어디 뒀지? v2

## 사업/앱 요약 (1쪽 구성)
- 목표: 물건의 정확한 이름이 기억나지 않아도 마지막 기록 위치를 사진으로 찾는다.
- 퍼소나(가상): 작은 방에서 공부·작업하는 대학생. 이어폰·충전선·열쇠를 여러 칸에 두고 출발 직전에 찾는다. 스마트폰 사용에 익숙하지만 재고 표를 관리할 의지는 낮다.
- 문제: 물건을 가지고 있다는 것은 알지만 어떤 칸에 두었는지 기억하지 못함. 등록에 많은 필드를 요구하면 기록 자체를 포기한다.
- 핵심 가치: 한 장의 사진 → AI 목록 초안 → 사용자 확인 → 특징으로 재발견. 정확도 보장보다 확인 가능한 사진·위치·시각을 제공한다.
- 차별화: 보험·자산 관리 중심의 복합 재고 정보보다 일상 재발견 과업에 집중한다. Itemtopia 공식 제품의 기능 부재를 단정하지 않는다.
- 성공 지표(향후 검증): 첫 예시 검색 후 위치 확인까지 3개 주요 행동 이내, 불확실한 이름을 사용자가 인지하는지, 모바일/넓은 화면에서 동일 흐름을 완료하는지. 실제 사용자 실험 결과가 아니다.
- 수익화·로그인·동기화는 과제 범위 밖이다.

## 피쉬본 — 여섯 관점
문제: **기록이 있어도 필요한 순간 물건의 위치를 확신하지 못한다.**

```text
사람: 이름/위치 기억의 한계 ───┐
방법: 물건마다 입력하는 부담 ──┤
데이터: 오래된 위치·잘못된 이름 ┤
                              ├── 위치를 믿고 찾기 어렵다
도구: AI 오인식·느린 응답 ─────┤
환경: 서랍/상자 이동·비슷한 물건 ┤
정보표현: 사진/위치 분리 ──────┘
```

우선순위 1: AI가 잘못 붙인 이름을 사용자가 확인하지 않고 확정하는 문제. 이유: 잘못된 등록은 이후 검색과 위치 확인을 동시에 약화한다. R2는 AI 도입 자체가 사용자 만족을 보장하지 않는다는 반론 근거이며, 구체적 오인식 빈도를 입증하는 자료는 아니다.

## 5 Why
1. 왜 찾지 못하는가? 기억한 특징과 저장된 이름이 연결되지 않을 수 있다.
2. 왜 이름이 연결되지 않는가? 자동 인식 이름이 실제 물건과 다를 수 있다.
3. 왜 잘못된 이름이 남는가? 자동 확정 시 사용자가 확인할 기회가 없다.
4. 왜 확인 기회를 생략하는가? 빠른 등록만을 최우선 목표로 잡기 때문이다.
5. 왜 속도만 우선하는가? 등록 완료를 성공으로 보고 나중에 다시 찾는 과업을 평가하지 않기 때문이다.

근본 설계 원인(가설): 등록 속도만 최적화하고 재발견의 신뢰도를 검증하지 않는 성공 기준. 해결: 기본 선택 + 불확실 항목 강조 + 수정 후 사용자 확인. 실제 인과관계는 향후 사용자 검증이 필요하다.

## 구현과 기획 연결
A 검색과 예시 → B 사진 위치 → C 발견 확인. D 사진·목록 확인은 기록의 신뢰도를 높이는 보조 흐름. 상세 요소·정보 전달 기준·상태관리 포인트는 `디자인가이드.md`에 통합했다. 발표용 PPT는 사용자 요청에 따라 이번 작업에서 제외했다.
